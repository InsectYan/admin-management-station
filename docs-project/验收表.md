# 验收表 / 智能质检页面

> **状态**：已落地（确定性核检 + 验收页 + 列表健康度 + 写章队列章级门禁；AI 深检可选）  
> **关联**：[`小说生成验证.md`](./小说生成验证.md) · [`小说平台Agent.md`](./小说平台Agent.md)  
> **入口**：列表「验收」/ 详情「验收核检」→ `/novels/:id/qa`  
> **风格**：清新森林风（`novel-sub-style.mdc`）

---

## 一、页面布局（已实现）

采用 **顶部状态栏 + 左预览 / 右质检** 工作台：

1. **顶部**：健康度评分（0–100）、各模块通过状态胶囊、一次性全检 / AI 深检开关  
2. **左侧设定速览**：按模块切换立意简介、世界观、门派、人物关系图、大纲、章节目录、正文/章级报告  
3. **右侧智能质检**：按模块折叠 findings；每模块可单独「检验本模块」；支持忽略  
4. **列表页**：仅增加 **健康度** 列/徽章与「验收」入口，不堆核检详情

---

## 二、核检模块（全流程）

对齐生成链路与验证计划：

| 模块 key | 名称 | 对应验收关注点 |
|----------|------|----------------|
| `basic` | 立意与简介 | 立意清晰度、简介完整度、类型 |
| `world` | 世界观与背景 | 纪元/地理/力量/社会史自洽 |
| `factions` | 门派组织 | 势力存在、重名、描述厚度 |
| `characters` | 人物与关系 | 主角、归属门派、关系边悬空 |
| `outline` | 篇幅大纲 | 大纲是否为空/过薄 |
| `content` | 章节目录 | `outline_ref` 悬空/缺失 |
| `continuity` | 正文连续性 | 组织名/地名粗检、过短正文 |

- **一次性检验**：`action=check_consistency`  
- **单模块检验**：`action=validate_module` + `module`  
- **单章检验**：`action=validate_chapter` + `chapter_id`（写章后自动；工作室「验证本章」；验收台可重验）

---

## 三、交互流程

1. 进入验收页 → `GET /api/novels/:id/qa`（无缓存则自动跑确定性全检并落 `setting_json.qa`）  
2. 「一次性全检」或「检验本模块」→ `POST /api/ai/review`  
3. 勾选「调用 AI 深检」时，BFF 在确定性结果上合并 `novel-review-skill` findings（Agent 不可用则静默跳过）  
4. 「忽略」→ `POST /api/novels/:id/qa/ignore`，重算分数  
5. 列表展示缓存的 `health_score` / `health_status`  
6. **写章门禁**：`写下一空章` / `续写队列` 保存后按绑定 `chapter_id` 跑 `validate_chapter`；`error` 级暂停队列，正文已保存不回滚
