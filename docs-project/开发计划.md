# 小说平台开发计划：从设定闭环到自动成书

> **版本**：v1.0 · 2026-08-30  
> **范围**：`project-sub/novel-sub` 列表 / 创建 / 详情（含单章开发）+ 对应 BFF / Skill  
> **目标**：创作者可以**自动化写出一篇完整小说**（设定齐、按目录写完全文、能读能导出）  
> **产品入口**：[小说平台Agent.md](./小说平台Agent.md)  
> **设计真源**：[Agent设计/readme.md](../project-sub/novel-sub/docs/Agent设计/readme.md) · [00-组件拆分](../project-sub/novel-sub/docs/Agent设计/00-组件拆分.md) · [11-单章开发](../project-sub/novel-sub/docs/Agent设计/11-单章开发.md)  
> **进度勾选**：[Agent组件开发进度](../project-sub/novel-sub/docs/Agent组件开发进度/readme.md)  
> **规范**：`.cursor/rules/` 之 `novel-sub-development.mdc`、`agent-skill-development.mdc`、`subapp-development.mdc`、`media-model.mdc`

本文是**下一阶段实施方案**，不是重写已落地的六步设定。已完成部分只作对照，不重复排期。

## 0. 结论（先读）

当前能力：**自动填设定**（一句话开书 → 六步向导逐步回填 → 详情只读查看）。  
缺口：**写不出一本完整小说**。开书计划停在「章节目录」；正文必须进详情、一章一章手点生成、应用、保存。

| 已有 | 没有 |
|------|------|
| 列表筛选 / 看板表格 / 快编 / AI 开书（只跑一步设定） | 开书跑完全文；列表看字数/章数；一键去写正文 |
| 创建六步 + 各步林间写手 + 封面出图 | 目录完成后进入单章开发；连续 dispatch 设定 |
| 详情单章坞 `fill_chapter_body` + 上下章 | 上一章结尾入参；写下一空章；批量续写；全书预览/导出 |
| 进度条 `progress_percent` 手填 | 进度跟已写字数 / 大纲目标走 |

**原则（沿用，本计划不推翻）**

- LLM 只在 Agent 平台；novel-sub BFF 只 `agentProxy` + 会话 + 业务落库。
- 前端禁止直连 `:4001`。
- Skill 不直写 `novel_db`。正文仍走现有 `PUT /api/novels/:id/chapters/:chapterId`。
- **默认仍是「生成 → 人确认 → 应用 → 保存」**。P0/P1 的「连续写」是用户点一次「写下一空章 / 续写未完成章节」后的**受控串行**，不是后台偷偷写完全书。
- 封面 / 视频继续走侧栏 `media_profile`，不走 `novel-writer-skill`。

**建议顺序**：P0 把正文接进主链路 → P1 能自动跑完一本并导出 → P2 长篇才稳（体检、记忆、版本）。

### 1.2 Agent 与计划

```text
fill_basic → fill_world → fill_factions → fill_characters → fill_outline → fill_chapters
                                                                              ↑ 停在目录
```

`DetailChapterStudio` 的 `form_snapshot` 现有：本章 id/title/faction/outline_ref/order、`body_excerpt` 前 800 字、门派/人物摘要、世界观 era/power。  
**没有**：上一章结尾、下一章大纲钩子、本章目标字数、全书已写字数。

### 1.4 开书 Dialog 已知偏差

`AiOpenBookDialog` 的 coverage 快照仍是五步（缺 `factions`），与六步计划不对齐。P0 一并修。

## 2. 目标用户路径（做完长什么样）

```text
列表「AI 开书」
  → 生成六步设定计划（仍可一步步确认）
  → 目录齐全后：「开始写正文」进入详情 tab=7 第一章
  → 「写下一空章」：带上一章结尾生成 → 应用到本章 → 保存 → 跳下一空章
  → 可选「续写未完成章节」：对空章队列串行，可暂停
  → 列表看到字数/章数；详情可全书预览；导出 TXT / Markdown
```

人工随时可改设定（跳回向导）和某一章正文。自动写只填**空章**，默认不覆盖已有正文。

## 4. 阶段方案

### 4.0 约定：连续写 ≠ Skill 直写库

| 模式 | 谁点 | 行为 |
|------|------|------|
| 单章对话 | 用户发一句 → 应用 → 保存 | 现状，保留 |
| 写下一空章 | 用户点一次按钮 | BFF 对**当前空章** turns → 前端应用 body → PUT 本章 → 跳下一空章（若用户勾选「保存后继续」） |
| 续写队列 | 用户点「续写未完成章节」 | 前端/BFF **串行**对空章列表重复「写下一空章」；可暂停；失败停在该章并提示 |

覆盖策略：仅 `word_count = 0` 或 body 空白的章；已有正文默认 skip。提供「强制重写本章」单独入口（仍要确认）。

## P0 — 把正文接进主链路（必须先做）

**完成定义**：目录保存后能进第一章；Agent 能带着上一章写下一空章；计划结构预留正文任务（执行可先只支持「下一空章」，不必一次写完全书）。

### P0-1 设定完成 → 单章开发

**用户**

- 向导第 6 步（章节目录）保存后，主按钮旁增加 **「开始写正文」**。
- 无章节时按钮禁用，提示先生成或添加章节。
- 列表「继续创作」旁增加 **「去写正文」**（有章节才显示）。
- 详情 tab 6 底栏「下一模块」已能进 tab 7；保持。向导「完成并返回列表」保留；从详情来的「完成并返回详情」可带 `tab=7`。

**落点**

| 层 | 文件 | 改动 |
|----|------|------|
| 前端 | `NovelCreateFooter.vue` / `useNovelCreateWizard.js` | 末步增加 `start-writing`；`router.push` 详情 `tab=7` + 第一章 `chapter` |
| 前端 | `NovelListPage.vue` | 卡片/表格增加「去写正文」 |
| 前端 | `useNovelDetail.js` | 已有 chapter query，确认第一章 id 用 `firstChapterId` |
| 文档 | `09-列表与详情.md` · `07-内容组织.md` · `11-单章开发.md` | 入口说明 |

**验收**

- [x] 目录至少 1 章时，「开始写正文」进入 `/novels/:id?tab=7&chapter=<first>`
- [x] 无章节时按钮不可用
- [x] 从详情进向导再「开始写正文」仍回同一本，不丢 `from`

### P0-2 单章 snapshot 补上下文

**入参（写入 `form_snapshot`，BFF `aiBoundContext` 原样转 Skill）**

```json
{
  "chapter": { "id", "title", "faction", "outline_ref", "order" },
  "body_excerpt": "当前章已有正文前 800 字",
  "prev_chapter": { "id", "title", "ending": "上一章末 600～800 字" },
  "next_outline": "下一章标题 + outline_ref 说明",
  "word_target": 3000,
  "words_written": 0,
  "factions": [],
  "characters": [],
  "world": { "era", "power_system" }
}
```

`word_target`：优先本章大纲节字数；否则用篇幅区间 / 章数估算（BFF 或前端二选一，**以 BFF 为准**，避免两边算法不一致）。

**落点**

| 层 | 文件 |
|----|------|
| 前端 | `DetailChapterStudio.vue` 的 `chapterSnapshot` |
| BFF | `GET .../chapters/:id` 已有 prev/next **元数据**；需 **prev body 摘要**（不要全文）。可在 GET 单章时返回 `prev_ending`，或单独 `GET .../chapters/:id/context` |
| BFF | `app/lib/aiBoundContext.js` 标签增加「上一章结尾」 |
| Skill | `novel-writer-skill` `fill_chapter_body` 模板：必须衔接 `prev_chapter.ending`，不得复述上一章，不得剧透 `next_outline` 以外的后文 |

**验收**

- [x] 写第 2 章时请求体含上一章结尾，不含其他章全文
- [x] 第 1 章 `prev_chapter` 为空
- [x] Network 无直连 `:4001`

### P0-3 「写下一空章」

**交互（详情 tab=7，须已「编辑」）**

- 按钮：**写下一空章**（浏览态禁用，与会话锁定一致）。
- 若当前章已有正文：跳到目录中**下一空章**再生成；若后面没有空章：提示「没有未写章节」。
- 流程：选中空章 → 自动发送约定 prompt（或静默 turns）→ 用户仍看到思考流 → 生成结束 **询问或默认勾选「应用到本章并保存」** → PUT → 定位下一空章。
- P0 建议：**默认勾选「应用并保存」**，仍展示结果，可点丢弃。不要完全静默。

**落点**

| 层 | 文件 |
|----|------|
| 前端 | `DetailChapterStudio.vue` + `useAiDock.js`（可抽 `writeNextEmptyChapter()`） |
| 前端 | 空章判定：`word_count === 0` 且 draft 空（`fetchChapterMeta` 已有字数） |
| BFF | 可复用现有 `POST .../turns/stream` + `PUT .../chapters/:id`，P0 **不必**新队列表 |

**验收**

- [x] 空章生成后应用并保存，目录树字数立刻更新
- [x] 已有正文的章不会被本按钮覆盖
- [x] 浏览态按钮禁用
- [x] 失败时正文不入库，提示可读

### P0-4 计划预留正文任务 + 修 coverage

**计划结构（`aiPlan.js`）**

在 `t_content` 之后增加：

| id | path | feature_key | writer_action | depends_on | 说明 |
|----|------|-------------|-----------------|------------|------|
| `t_bodies` | `plan.bodies` | `chapter` | `fill_chapter_body` | `t_content` | **逻辑任务**：表示「按目录写正文」；dispatch **一次只写一章**（body 带 `chapter_id`） |

coverage：`bodies` = 全部目录章 `word_count > 0`。有任意空章则为未完成。

**P0 dispatch 行为**

- 用户在计划坞点「执行下一步」且当前是 `plan.bodies`：BFF 选**第一个空章**调 `chapter` turns，返回 `{ chapter_id, step: 7 }`，前端跳转详情单章而不是向导 step。
- 不在 P0 一次写完全书。

**同时修**

- `AiOpenBookDialog` snapshot.coverage 补 `factions`（及后续 `bodies: false`）。
- orchestrator Skill 文档 / 模板：任务允许 `plan.bodies`；sanitize 强制插入该步。
- `08-总任务拆分.md`、`SKILL-任务拆分.md` 同步。

**验收**

- [x] 新计划 7 项，含 `plan.bodies`，依赖章节目录
- [x] 目录未完成前 dispatch bodies → 409 `DEPENDENCY_BLOCKED`
- [x] 执行 bodies 打开详情 tab=7 对应空章，坞可生成
- [x] 开书 Dialog 不再把「有世界观无门派」当成可跳过人物依赖的错误 coverage

### P0-5 列表「去写正文」

见 P0-1。表格操作列、看板按钮同时加。无章节时隐藏或禁用。

## P1 — 能自动跑完一本

**完成定义**：用户确认设定后，可对空章队列串行续写；列表能看出写到哪；能预览全书并导出。

### P1-1 续写未完成章节（队列）

**产品**

- 详情单章栏 / 列表（有空章时）：**续写未完成章节**。
- 弹出确认：将写入 N 个空章，可随时暂停；不覆盖已有正文。
- 进度：当前「第 i / N 章 · 标题」；失败停在该章，保留已成功章节。
- 实现倾向：**前端编排串行**（已有 stream + PUT），BFF 增加 `GET /api/novels/:id/chapters/empty` 返回空章 id 列表即可。若一次请求过长再升「作业表」。

**不建议 P1 就做**：独立 worker、Redis 队列、Skill 直写库。

**验收**

- [x] 3 个空章可连续写完，刷新后三章均有 `word_count`
- [x] 暂停后已写章保留，未写章仍空
- [x] 某一章 500/超时：前面已保存，后面不写，提示章标题

### P1-2 进度与列表字段

**算法（单一实现，前后共用或只算 BFF）**

```text
written = sum(chapter_bodies.word_count)
target  = 大纲字数合计；若无则用篇幅区间中值 × 系数
percent = clamp(round(written / target * 100), 0, 100)
chapters_done / chapters_total
```

- `GET /api/novels` 每条带：`word_count`、`chapter_written`、`chapter_total`、`progress_percent`（可派生，**不再要求用户手填**；快编里的完成度改为只读或「覆盖标记」）。
- 看板进度条、表格列、详情底栏用同一套数。

**落点**：`service/novel.js` list 聚合 `novel_chapter_bodies`；`buildProgressMeta` 与列表对齐。

**验收**

- [x] 写一章保存后，列表与详情百分比上升（允许缓存，保存后应刷新）
- [x] 快编不再把过期手填 percent 盖掉派生值（若保留字段，保存设定时不要误覆盖）

### P1-3 全书预览

**交互**

- 详情增加阅读入口（tab 或单章页「全书预览」）：按卷/章顺序 Markdown 渲染，章间锚点，目录可跳。
- 只读；改正文仍回单章编辑。
- 正文用 `NovelMarkdown`，禁止未消毒 `v-html`。

**数据**

- `GET /api/novels/:id/chapters/export` 或 `GET .../reader`：返回 `{ volumes: [{ title, chapters: [{ id, title, body, word_count }] }] }`。  
  注意体积：可按卷分页；P1 先整本（中短篇），超阈值再拆。

### P1-4 导出 TXT / Markdown

- 前端用 P1-3 同一 API 下载：`书名.md` / `书名.txt`。
- 格式：`# 书名` → `## 卷` → `### 章` + 正文。
- 不接 EPUB（P2 可选）。

**验收**

- [x] 预览顺序与目录树一致
- [x] 导出文件 UTF-8，空章显示占位「（未撰写）」或不输出该章（产品选一种，推荐占位以免章号错位）

### P1-5 设定计划可连续执行（可选增强）

- [x] 开书 / 「补全全部缺口」增加 **「连续执行设定（仍逐步展示）」**：自动 dispatch 直到 `t_content` 完成，每步应用进表单并保存草稿，**停在写正文前**
- [x] 每步仍走现有 apply 语义；用户可取消
- [x] P1 不做「连续执行时自动写完全部正文」（那是队列 P1-1，入口在详情）

## P2 — 写长了才稳

### P2-1 设定体检 `novel-review-skill`

设计原文 Phase 4。详情按钮「设定体检」：人物 vs 世界观 vs 大纲 vs 已写正文矛盾列表。只出报告，不改字段。落点新 Skill + `POST /api/ai/review`。

### P2-2 跨章记忆

同书 `feature_key=chapter` 会话注入：主要人物人设短表、已发生情节要点（BFF 从设定 + 近 N 章摘要拼，限制 token）。减少连写漂移。

### P2-3 正文版本

`novel_chapter_body_revisions`（chapter_id, body, word_count, created_at）。每次 PUT 插一版，列表「恢复此版」。P2 再做，避免 P0 改表拖慢主链路。

### P2-4 复制开书 / 看板操作补齐

- 从已有小说复制 `setting_json`（不含 bodies 或可选空正文）建新草稿。
- 看板卡片补删除、快编。
- 枚举建议：开书 intent 可建议类型/篇幅，仍由用户在表单确认（保持「枚举不让 AI 直接写 id」）。

### P2-5 EPUB / 片头视频

非目标除非产品单列。视频必须 `media_profile`。

## 6. API / 数据（按阶段新增）

现有单章 API 保持：`GET/PUT /api/novels/:id/chapters/:chapterId`、`GET .../chapters` 元数据。

| 阶段 | 方法 | 路径 | 说明 |
|------|------|------|------|
| P0 | GET | `/api/novels/:id/chapters/:chapterId` | 扩展：`prev_ending`、`next_meta`、`word_target`（或另开 context） |
| P1 | GET | `/api/novels/:id/chapters/empty` | 空章 id 顺序列表 |
| P1 | GET | `/api/novels/:id/reader` | 按卷章正文（预览/导出） |
| P1 | GET | `/api/novels` | 列表项增加 `word_count`、`chapter_written`、`chapter_total` |
| P2 | POST | `/api/ai/review` | 体检 |
| P2 | GET | `/api/novels/:id/chapters/:chapterId/revisions` | 版本列表 |
| P2 | POST | `/api/novels/:id/clone` | 复制设定 |

P0 **不强制**新表。P2 版本表才改 `init.sql` + migration，并走 schema 同步规范。

`POST /api/ai/dispatch`：识别 `plan.bodies` 时选空章 + `feature_key=chapter`，响应带 `chapter_id`、`tab: 7`。

## 7. Agent 改动

| 阶段 | Skill | 内容 |
|------|-------|------|
| P0 | `novel-orchestrator-skill` | plan 增加 `plan.bodies`；coverage 含 bodies；模板禁止把「写正文」并进 `fill_chapters` |

落点目录：`agent-management-master/plugins/`（与现网 writer/orchestrator 一致；规则默认 sub，以仓库实际插件目录为准）。  
禁止 orchestrator HTTP 调 writer；串行只在 novel BFF。

## 8. 风险与约束

| 风险 | 处理 |
|------|------|
| 长篇一次生成超时 | 一章一次 turns；队列串行；超时停在该章 |
| 上下文窗口爆 | 只传上一章结尾 + 本章大纲 + 人物短表，不传全书 |
| 用户误覆盖已写章 | 默认只写空章；重写要二次确认 |
| 进度手填 vs 派生冲突 | P1 起以派生为准，文档写清 |
| 导出体积 | P1 中短篇整本；超限按卷 |
