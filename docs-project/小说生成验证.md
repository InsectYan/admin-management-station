# 小说章节生成验证 Agent 计划

> **状态**：设计 + 首版落地中（BFF 确定性核检 / 验收页 / `novel-review-skill` 骨架已接；章级队列门禁待挂）  
> **关联**：[`小说平台Agent.md`](./小说平台Agent.md) · [`验收表.md`](./验收表.md) · [`开发计划.md`](./开发计划.md) P2-1 · [`Agent设计/readme.md`](../project-sub/novel-sub/docs/Agent设计/readme.md) §4.3  
> **落点 Skill**：`agent-management-master/plugins/novel-review-skill/`（同步约定见 `agent-skill-development.mdc`）  
> **原则**：只出报告、默认不改正文/设定；生成链路绑定章节 `chapter_id`，验证结果挂同一章
> **产品入口**：详情 / 列表 → 验收核检页 `/novels/:id/qa`

---

## 0. 要解决什么

自动写章时，模型容易「发明」设定库里不存在的人、组织、地名，或违背力量体系 / 大纲节点。现有 writer 只在回复里软提醒一致性，**没有独立验收**。

本计划定义 **章节生成验证 Agent**：

1. **覆盖大纲向导全部功能模块**（基础信息 → 世界观 → 门派 → 人物 → 大纲 → 章节目录 + 正文连续性）。
2. **每生成一章，对每个模块各跑一轮校验**（例如写到第五章，该章正文要分别对照人物库、门派库、地理与力量体系、大纲节点等）。
3. 结果结构化为 findings，供 UI 展示、队列暂停策略与后续人工修正。

## 1. 当前自动生成能力梳理（真源）

### 1.1 功能模块与生成 Skill

| 模块 | 向导/详情 | scene / action | 产出落点 | 是否自动成书链路 |
|------|-----------|----------------|----------|------------------|
| 基础信息 | 创建步 1 | `basic*` / `fill_basic` · `rewrite_field` | 书名、立意、简介；类型等枚举手选 | orchestrate `plan.basic` |
| 世界观 | 创建步 2 | `world*` / `fill_world` | `setting_json.world`：纪元、地理、社会、力量、科技、史、时间线 | `plan.world` |
| 门派组织 | 创建步 3 | `factions*` / `fill_factions` | `setting_json.factions[]` | `plan.factions` |
| 人物 | 创建步 4 | `characters*` / `fill_characters` | `characters[]` + `character_edges[]` | `plan.characters` |
| 篇幅大纲 | 创建步 5 | `outline*` / `fill_outline` | `outline.volumes[]`（卷/组/节 + 字数目标） | `plan.outline` |
| 章节目录 | 创建步 6 | `content*` / `fill_chapters` | `chapters[]`：标题、阵营倾向、`outline_ref`、顺序 | `plan.content` |
| 单章正文 | 详情 tab=7 | `chapter` · `chapter.body` / `fill_chapter_body` | `novel_chapter_bodies.body`（仅正文） | `plan.bodies` / 写下一空章 / 续写队列 |
| 开书计划 | 详情计划坞 | `orchestrate*` / `plan` | `tasks[]`，不写正文 | 列表「AI 开书」 |

依赖顺序（orchestrator 与写设定时必须遵守）：

```text
basic → world → factions → characters → outline → content → bodies（逐空章）
```

### 1.2 正文自动生成入口

| 入口 | 行为 |
|------|------|
| 详情「写下一空章」 | 找当前及之后第一个空章 → 林间写手 turns → 按 **绑定 chapter_id** PUT |
| 详情 / 列表「续写未完成章节」 | 空章队列串行；可暂停；失败停该章 |
| 开书计划 `plan.bodies` | BFF 取第一个空章 dispatch，跳转详情 tab=7 |
| 坞内自由对话 | 同 `fill_chapter_body`；用户点「应用到本章」 |

写章时传给模型的核心上下文（`form_snapshot` / `buildChapterAgentSnapshot`）：

- 本章元数据：`id, title, faction, outline_ref, order`
- `body_excerpt`、`prev_chapter.ending`、`next_outline`、`word_target`、`words_written`
- 人物/门派短表、世界观 `era` + `power_system`（**完整地理/时间线等未全量注入**）

### 1.3 已有缺口（验证 Agent 补上）

| 缺口 | 说明 |
|------|------|
| 无独立 review Skill | 设计稿 `novel-review-skill` / `check_consistency` 未实现 |
| 写章后无门禁 | 队列写完即保存，不核对设定库 |
| 地理无结构化实体 | 仅有 `world.geography` 自由文本，校验需抽取 + 对照文本 |
| 章级 snapshot 偏瘦 | 完整世界字段、人物小传未全部进入写章上下文，更易漂移 |

## 2. 验证 Agent 定位

| 项 | 约定 |
|----|------|
| Skill 名 | `novel-review-skill` |
| 主 action | `validate_chapter`（章级，本计划主交付） |
| 附 action | `check_consistency`（全书设定体检，对齐原 P2-1） |
| scheme | `react`（短报告）或 `loop`（长章多模块逐条） |
| 谁调度 | `novel-sub` BFF；前端不直连 `:4001` |
| 写库 | **默认不写**；只返回 `findings[]` + `summary` |
| 绑定 | 请求必须带 `novel_id` + `chapter_id`；报告归属该章 |

与 writer 的关系：

```text
fill_chapter_body（生成，绑定 chapter_id）
        ↓ 得到 body（可先暂存 / 已 PUT）
validate_chapter（按模块逐项对照 setting_json + 章元数据）
        ↓ findings
前端展示 / 队列策略（通过则继续；高严重度可暂停）
```

## 3. 触发时机

### 3.1 必做：每章生成后

以下路径在 **本章正文已产出且已绑定 `chapter_id`** 之后，立刻跑一轮 `validate_chapter`：

1. 「写下一空章」保存成功后  
2. 「续写未完成章节」队列中每一章保存成功后  
3. 开书计划 `plan.bodies` 单章 dispatch 成功后  
4. （可选）坞内「应用到本章」并保存后  

**硬规则**：验证输入使用生成时绑定的 `chapter_id` 与该章 `body`，**禁止**用当前浏览中的章节 id（与「切章误写」同类问题）。

### 3.2 可选：全书体检

详情「设定体检」按钮 → `check_consistency`：不依赖单章 body，扫设定自洽 + 已写正文抽样。可与章级验证共用 Skill、不同 action。

### 3.3 队列策略（建议）

| findings 最高级别 | 队列行为（可配置） |
|-------------------|-------------------|
| `error` | 暂停续写，停留该章，展示报告 |
| `warning` | 继续，章旁角标提示 |
| `info` | 仅记录 |

首版默认：`error` 暂停，`warning` 不阻断。

## 4. 模块覆盖矩阵（每章必须各验一次）

每一章验证 = **一次 invoke**，内部按模块产出分组 findings（或 BFF 串行多 check 再合并；推荐单次 invoke + 模块分区，省往返）。

| # | 模块 | 对照真源 | 本章至少要做的检查 |
|---|------|----------|-------------------|
| M1 | 基础信息 | novels 列 + 题材/篇幅 | 基调/类型/题材是否明显跑偏；篇幅定位是否与 `word_target` 量级冲突 |
| M2 | 世界观 · 地理 | `world.geography`（及正文地名抽取） | 出现的地点/区域是否能在地理描述中找到依据；禁止无中生有的大陆/城邦（高严重度） |
| M3 | 世界观 · 力量/科技 | `world.power_system` · `technology` | 功法、境界、道具是否违背已写力量/科技设定 |
| M4 | 世界观 · 纪元社会史 | `era` · `social_rules` · `history_notes` · `timeline` | 时代称谓、制度、重大史实是否冲突；时间线事件是否被正文改写 |
| M5 | 门派组织 | `factions[]` | 正文出现的门派/国家/势力名称是否在库中；总部、阵营、戒律是否矛盾 |
| M6 | 人物 | `characters[]` | 出场人名是否在人物库；角色定位（主/配/反）是否严重错位 |
| M7 | 人物关系 | `character_edges[]` + `faction_id` | 称谓/敌友/师徒等是否与边关系或所属门派矛盾 |
| M8 | 篇幅大纲 | `outline.volumes` + 本章 `outline_ref` | `outline_ref` 是否悬空；正文事件是否偏离该大纲节点意图 |
| M9 | 章节目录 | 本章 `chapters[]` 元数据 | 标题主题是否被写成另一章；`faction`（正/邪/中）倾向是否明显相反 |
| M10 | 正文连续性 | `prev_ending` · `next_outline` · 字数 | 是否与上章结尾脱节；是否剧透超出 `next_outline`；字数相对 `word_target` 是否严重偏离 |

> **说明**：地理无独立表，M2 以「正文 NER/模型抽取地名 → 与 `geography` 文本及已出现别称对照」实现；无法识别的专有名词标 `warning` 并建议补进世界观或人物/门派库。

## 5. 校验细则（实现清单）

### 5.1 M6 / M5 — 实体存在性（优先落地）

1. 从本章 `body` 抽取候选实体：人名、组织名、地名。  
2. 与 `characters[].name`、`factions[].name`、地理文本做匹配（含别称：可用 `label` / 描述内提到的简称，首版可模糊包含）。  
3. **库中不存在** → `error`（或可配置为 warning）：`code: unknown_character | unknown_faction | unknown_place`。  
4. 库中存在但属性冲突（阵营、门派归属）→ `warning` / `error`。

### 5.2 M7 — 关系与归属

- 正文写「A 为 B 师尊」但 edge 为 `enemy` → 冲突。  
- 正文称某人属某门派，但 `faction_id` 指向另一门派 → 冲突。  
- 门派 `member_ids` 与人物 `faction_id` 双向不一致 → 设定层问题，可记入章报或留给全书体检。

### 5.3 M8 / M9 — 大纲与目录

- `outline_ref` 空或找不到节点 → `error`（`dangling_outline_ref`）。  
- 大纲节点标题/摘要与正文主线无关 → `warning`。  
- 本章 `order` 与上下章衔接（若有 `prev_ending`）明显错位 → `warning`。

### 5.4 M2–M4 — 世界观

- 力量体系：越级、体系外能力 → 对照 `power_system`。  
- 地理：新城、新国未在 `geography` 出现 → `unknown_place`。  
- 时间线：正文年份/事件与 `timeline[]` 矛盾 → `timeline_conflict`。

### 5.5 M1 / M10 — 基调与连续

- 类型/题材（如「凡人流」）正文却大面积神战无铺垫 → `tone_drift`。  
- 字数 `< 40%` 或 `> 200%` of `word_target` → `word_target_miss`（warning）。  
- 复述上章大段 / 剧透下章钩子外情节 → `continuity_*`。

### 5.6 确定性预检（BFF，不调用 LLM）

在 invoke Skill 前由 BFF 先跑：

| 预检 | 结果 |
|------|------|
| `chapter_id` 属于该小说 | 否则 422 |
| body 非空 | 否则跳过或 info |
| `outline_ref` 能解析到大纲节点 | 失败直接写入 findings |
| 目录章 `faction` 枚举合法 | 非法则 findings |

确定性结果与模型结果合并，避免纯 LLM 漏检结构问题。

## 6. 输入 / 输出契约

### 6.1 BFF API（规划）

```http
POST /api/ai/review
```

```json
{
  "action": "validate_chapter",
  "novel_id": 123,
  "chapter_id": "ch_xxx",
  "body": "可选；缺省则读库中该章正文",
  "options": {
    "modules": ["basic", "world", "factions", "characters", "outline", "content", "continuity"],
    "fail_level": "error"
  }
}
```

全书体检：`action: "check_consistency"`，可不传 `chapter_id`。

### 6.2 Skill 入参（BFF 组装）

BFF 注入完整对照包（比写章 snapshot 更全）：

```text
chapter_meta          # 本章目录字段
body                  # 本章全文（可截断策略：超长则分段 + 汇总）
prev_ending           # 上章末
next_outline
word_target / words_written
basic                 # 含水合后的类型/题材/篇幅名
world                 # 全字段含 geography / timeline
factions[]            # 全字段
characters[]          # 含 personality / background / goal / faction_id
character_edges[]
outline_tree          # volumes 全树
outline_node          # 由 outline_ref 解析出的节点
```

### 6.3 出参

```json
{
  "chapter_id": "ch_xxx",
  "passed": false,
  "summary": "发现 2 个错误、3 个警告",
  "findings": [
    {
      "id": "f1",
      "module": "characters",
      "code": "unknown_character",
      "severity": "error",
      "entity": "玄机老人",
      "message": "正文出现人物「玄机老人」，人物模块中不存在",
      "evidence": "……原文摘录……",
      "suggestion": "补入人物库，或改为已有角色「玄机子」"
    }
  ],
  "modules_checked": ["basic", "world", "factions", "characters", "outline", "content", "continuity"]
}
```

| 字段 | 说明 |
|------|------|
| `module` | `basic` \| `world` \| `factions` \| `characters` \| `outline` \| `content` \| `continuity` |
| `severity` | `error` \| `warning` \| `info` |
| `code` | 稳定机器码，便于前端与队列策略 |
| `evidence` | 正文短摘录，便于定位 |
| `passed` | 无 `error` 级则为 true（warning 仍可通过） |

## 7. 前端与队列接入

### 7.1 `DetailChapterStudio`

- 单章写完 → 调 `POST /api/ai/review`（带绑定 `chapter_id`）。  
- 报告展示：章旁抽屉 / 队列条下方 findings 列表。  
- 续写队列：按 §3.3 决定是否 `pauseQueue`。

### 7.2 详情入口

- 「设定体检」→ `check_consistency`（全书）。  
- 单章「验证本章」→ 手动重跑 `validate_chapter`。

### 7.3 与生成绑定

```text
writeOneEmptyChapter(boundChapterId):
  sendText → applyPending → persistChapterBody(boundChapterId, body)
  → reviewChapter(boundChapterId)   // 同一 id，禁止用当前 UI chapterId
```

## 10. 验收标准

- [ ] 生成第五章后，报告中 `modules_checked` 含全部模块，且对人物/门派/地理等均有显式通过或 findings。  
- [ ] 正文故意写入不存在的人名「测试散人甲」→ 必出 `unknown_character` error。  
- [ ] 正文故意写入不存在的门派 → `unknown_faction`。  
- [ ] `outline_ref` 悬空 → 确定性预检即报错，不依赖模型。  
- [ ] 生成过程中切换浏览章节，验证仍针对 **绑定 chapter_id**，不串章。  
- [ ] 续写队列在 error 时可暂停，已通过章保留。  
- [ ] Skill / BFF **不**自动改 `setting_json` 或正文。

## 11. 非目标（本阶段不做）

- 替代人工审稿；报告是辅助门禁，不是终审。
