# 01 会话与上下文

> 类型：基建（无独立页面）  
> 依赖：现有 `novels.id`  
> 被依赖：所有功能组件、[02-表单AI坞](./02-表单AI坞.md)

生成结果会反复改，必须把 **思考过程 + 用户话 + 建议 patch + 是否已应用到表单** 存下来。同一本小说、同一个功能（步骤）是一组会话，组内可新开多条线程。

---

## 1. 前端

不单独做「会话管理页」。坞顶（竖栏上方或底栏浮层顶）：

- 下拉：当前 `feature_key` 下的会话列表（标题默认取首条用户话截断）
- 「新开会话」：清空线程，保留表单；新 `session_id`
- 历史按 **完整对话流** 展示（见 02），不再压成「最近 2 轮」

思考过程：每轮一条可折叠块，流式阶段用平台 SSE `status.phase` 文案（如「发散创意」「收成字段」）。**思考文本不写入表单字段。**

应用表单后：该轮标记 `applied=true`，下一轮请求带上「已应用 patch 摘要」，避免 Agent 忘掉用户刚采纳的书名。

---

## 2. 服务端（仅接口 + 落库，无 LLM）

表放 **novel_db**（业务会话）。Skill 自己的 run 表仍在 Agent 库，两套不要混。

### 2.1 表

**`novel_ai_sessions`**

| 列 | 说明 |
|----|------|
| `id` | PK |
| `novel_id` | 可空（开书尚未 create） |
| `feature_key` | `basic` / `world` / `characters` / `outline` / `content` / `orchestrate` / `quick_edit` |
| `title` | 列表展示 |
| `status` | `active` / `archived` |
| `bound_context_json` | 开会话时冻结的上下文指针：当时的 step、已应用字段 path 列表 |
| `created_at` / `updated_at` | |

唯一检索：`(novel_id, feature_key, status)` 下列表，**不**限制只能一条 active（允许并行试稿，坞里切换）。

**`novel_ai_messages`**

| 列 | 说明 |
|----|------|
| `id` | PK |
| `session_id` | FK |
| `role` | `user` / `thinking` / `assistant` / `system` |
| `content` | 文本 |
| `target_fields_json` | 本轮主题 path 数组，如 `["title","creative_intent"]` |
| `patch_json` | 建议写入的局部对象（未应用也可存） |
| `applied` | bool，用户点「应用到表单」后 true |
| `trace_id` | 调 Agent 的追踪 |
| `created_at` | |

DDL 走 `database/init.sql` + migration + Model，启动 schema 同步。

### 2.2 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/ai/sessions` | query：`novel_id`、`feature_key` |
| POST | `/api/ai/sessions` | body：`novel_id?`、`feature_key`、`title?` |
| GET | `/api/ai/sessions/:id/messages` | 按时间升序 |
| POST | `/api/ai/sessions/:id/turns` | **主入口**：见下 |
| POST | `/api/ai/sessions/:id/apply` | `{ message_id, paths[] }` 只改 `applied` 与摘要，**不写 novels**（表单仍由现有 PUT 保存） |
| PATCH | `/api/ai/sessions/:id` | 归档 |

**`POST .../turns` 请求**

```json
{
  "message": "起个冷门一点的书名",
  "target_fields": ["title"],
  "form_snapshot": {},
  "enum_catalog": {},
  "pipeline": ["brainstorm", "writer"]
}
```

`target_fields` 可空：交给 Agent 识别，响应里带回建议 Tab，前端待确认。

**响应**

```json
{
  "session_id": 1,
  "messages": [
    { "role": "thinking", "content": "..." },
    { "role": "assistant", "content": "可选三个名字…", "target_fields": ["title"], "patch": { "title": "……" } }
  ],
  "trace_id": "..."
}
```

实现：`controller/aiSession.js` + `service/aiTurn.js`。`aiTurn` **只**：读会话历史 → 调 `agentProxy`（按 `pipeline` 串行）→ 写 messages。禁止在 service 里拼 prompt。

`pipeline` 默认：

| feature | 默认 pipeline |
|---------|----------------|
| `basic` / `world` / `characters` / `outline` | `brainstorm` → `writer` |
| `content` | 可仅 `writer`（章节标题偏结构） |
| `orchestrate` | 仅 `orchestrator` |
| 用户已把 Tab 锁死且只要改写 | 可只 `writer`（body `pipeline: ["writer"]`） |

枚举：turns 内由 service 调已有 `novelEnum`，塞进 proxy payload，前端也可带缓存。

## 3. Agent

本组件 **不对应新 Skill**。会话历史由 BFF 在 invoke 时塞进 `messages[]` / `prior_turns`。

平台 `session_id` 字段：传 `novel-{novelId}-{feature}-{sessionPk}`，便于日志。记忆若开，用 writer/brainstorm 的 `memoryConfig`，**不要**用平台 memory 替代 `novel_ai_messages`（后者要能按小说查询）。

思考过程：优先吃 SSE `status` + 最终 JSON 的 `output.thinking`；BFF 合成一条 `role=thinking` 再给前端。

---

## 4. 上下文绑什么

每次 turn，BFF 组装 `bound_context`（截断，避免撑爆）：

| 来源 | 用途 |
|------|------|
| 本会话最近 N 条（含 thinking 摘要、已 applied patch） | 改稿连续 |
| 当前步 `form_snapshot` | 知道空/已填；BFF 会把类型/题材/篇幅/读者 **id 解析成中文名** 再交给 Agent |
| 其他步 `setting_json` 摘要 | 人物要看世界观，大纲要看人物名 |
| `enum_catalog` | 给 Agent 的是名称目录（无 id），禁止瞎编类型 |
| `target_fields` | 本轮主题 |

`novel_id` 为空时（列表开书尚未 create）：会话仍建，create 成功后 `PATCH` 补上 `novel_id`。

## 5. 验收

- [ ] 同一 `novel_id + basic` 可列出多条会话并切换，消息不串
- [ ] turns 失败时用户消息可记或不记，但不得写半截 patch 到 novels
- [ ] apply 不调用 `PUT /novels`，只打标
- [ ] 思考与助手回复分两条 message
