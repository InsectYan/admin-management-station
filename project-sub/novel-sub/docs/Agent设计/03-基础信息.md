# 03 基础信息

> 页面：`/novels/create` step=1（`StepBasicInfo.vue`）；列表 `NovelEditDialog` 可共用坞  
> `feature_key`：`basic`  
> 壳：[02-表单AI坞](./02-表单AI坞.md) · 会话：[01](./01-会话与上下文.md)

本步是 **第一条闭环**：自然语言 → 确认主题 Tab → 写回书名/立意等。书名不再单独做聊天窗；立意不再做「上结果下提示词」。

---

## 1. 前端

表单保持现有字段。向坞 **插入** `scenes[]`（结构见 [02](./02-表单AI坞.md)），建议一级扁卡（无子级也可）：

| id | title | scene | path | 默认露出 |
|----|-------|-------|------|----------|
| title | 小说名称 | basic.title | title | 是 |
| intent | 创作立意 | basic.intent | creative_intent | 是 |
| summary | 小说简介 | basic.summary | summary | 是 |
| genre / themes / length / audience / pace | 类型等选项 | — | — | **禁止选择**；表单里手选，AI 不生成 |

不进 scenes：`author_name`、`cover_url`、`progress_*`、`status`。也可再包一层父卡 `basic`（title=基础信息，`scene: 'basic'`，`action: 'fill_basic'`）把上表收成 children，与 04 世界观同一套父/子交互。

占位符：「起个名字 / 帮我凝练立意」。类型、题材、篇幅、读者、节奏在表单里手选。

应用：`merge` 进 `basicForm`。`genre_path` 必须是 catalog 里的 id 数组；`theme_ids` 同理。

编辑弹窗：同一 `AiFormDock`，`feature_key` 仍为 `basic`（同一会话组，和向导共享上下文）。弹窗高度有限，坞默认折叠为「一行输入 + 展开」。

---

## 2. 服务端

仅 `POST /api/ai/sessions/:id/turns`（JSON）与 `.../turns/stream`（SSE）。本步 `pipeline` 默认 `["brainstorm","writer"]`。

BFF **不**把类型/题材/篇幅/读者/节奏交给 writer 生成；`sanitizePatch` 只保留 `title` / `creative_intent` / `summary`。结构化 scene 直接 400 `SCENE_STRUCTURAL`。

无草稿时：允许 turns（`novel_id` 空）。用户点保存草稿仍走现有 `POST /api/novels`；成功后把当前 session `novel_id` 补上。

---

## 3. Agent

| 顺序 | Skill | action | 作用 |
|------|-------|--------|------|
| 1 | `novel-brainstorm-skill` | `ideate` | 书名候选、立意火花、卖点；**不要枚举 id** |
| 2 | `novel-writer-skill` | `fill_basic` | 吃火花 + 表单 + catalog → `patch` |

用户已锁定 Tab 且说「把立意改短」：可 `pipeline: ["writer"]`，`rewrite_field` / `fill_basic` 只含 `creative_intent`。

`target_fields` 识别示例：「起个名字」→ `["title"]`；「帮我写简介」→ `["summary"]`。类型等枚举不进 target_fields。

## 4. 验收

- [ ] 「起个偏冷门的书名」→ 待确认 Tab 含小说名称 → 应用后只有 `title` 变
- [ ] 类型/题材/篇幅/读者/节奏场景卡不可点；AI 不改这些表单控件
- [ ] 思考过程生成中流式展开，整轮结束后折叠
- [ ] 不点应用，保存草稿不含本轮 AI 值
