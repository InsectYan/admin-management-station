# 11 单章开发

> 页面：仅详情 `?tab=7` `DetailChapterStudio`  
> 创建向导、编辑弹窗 **不展示**  
> `feature_key`：`chapter`

## 布局

```
[模块导航] | [章节目录树] | [会话 | 人员关系 | 门派 | 大纲 | 世界观] | [正文]
```

章节目录最小 230px（border-box 列宽），右缘可拖动改宽；中间栏不得进入左侧 230px。

中间栏 Tab：第一个 **会话** 是操作（林间写手坞）；其余只读查看。

正文区：只加载当前章；上一章 / 下一章翻页。

详情页整体是设定**查看页**。坞用 `always-interactive`，避免误走「没 novelId 先保存基础信息」整栏禁用；会话是否可操作跟右侧「编辑 / 浏览」走（`sessionLocked`）。

**可编辑开关**（仅正文栏一枚）：

| 状态 | 正文 | 会话 Tab |
|------|------|----------|
| 浏览 | Markdown 展示 | 历史只读；新开 / 发送 / 应用禁用 |
| 编辑 | textarea | 可聊天、新开、发送、应用到本章 |

「应用到本章」写入正文（须已在编辑）。正文输入框改字或应用后，标题栏与目录树字数立刻按同一套算法重算（未保存标「未保存」）。关掉编辑时若有未保存改动，先问是否保存。

## 数据

正文在 `novel_chapter_bodies`，不进 `setting_json`，也不随 `GET /novels/:id` 返回。

- `GET /api/novels/:id/chapters`：字数元数据
- `GET/PUT /api/novels/:id/chapters/:chapterId`：单章正文 + prev/next + `prev_ending` / `next_outline` / `word_target`

## Agent

writer `fill_chapter_body`，patch 只有 `body`。

snapshot（BFF 为准）带：

- 当前章元数据与 `body_excerpt`（前 800 字）
- `prev_chapter.ending`（上一章末 800 字；第 1 章为空）
- `next_outline`（下一章标题 + outline_ref）
- `word_target`（大纲节字数，否则篇幅区间 / 章数估算）
- 人物/门派短表、世界观 era / power_system

不带其他章全文。

GET/PUT 单章另回 `prev_ending`、`next_outline`、`word_target`。

编辑态可点 **写下一空章**：只写当前或之后的空章；默认勾选「应用并保存」，生成后 PUT，再定位下一空章。浏览态禁用。

**续写未完成章节**：确认后按空章队列串行生成→应用→保存，可暂停；失败停在该章，已写章保留。列表「续写」带 `?queue=1` 打开确认。

**全书预览**（详情 tab=8）：同一 `GET /reader` 渲染 Markdown，导出 TXT / Markdown；空章占位「（未撰写）」。

开书计划 `plan.bodies` 执行下一步时，BFF 选第一个空章调 `chapter.body`，前端跳详情 tab=7，不一次写完全书。
