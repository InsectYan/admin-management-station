# 组件拆分

> 总览仍看 [readme.md](./readme.md)。本文只回答：**拆成几块、谁共用谁、开发顺序**。  
> 约定：**一个组件一份三端方案**（本目录独立 `.md`）。Vue 实现上多数功能组件 **挂同一套坞**，不按字段各做聊天框。

---

## 1. 交互原则（相对总览的修正）

总览里的「字段旁 Trigger + 独立抽屉」**不再作为主路径**。字段挤进双输入框或独立聊天窗会把表单撑乱。

改为：

| 原则 | 做法 |
|------|------|
| 表单保持表单 | 原有 `el-input` / 级联 / 多选不动；AI 不改字段控件结构 |
| 一坞管本步 | [表单AI坞](./02-表单AI坞.md) 默认 **竖栏贴左侧菜单**，不吃表单高度；可切底栏（图标条 + 对话浮层） |
| 场景卡数据插入 | 步骤传入 `scenes[]`（父/子、`scene`/`skill`/`path`）；勾父=全部叶子，勾子=单项 |
| 本次主题 | 场景卡勾选 = 本轮约束；Agent 识别结果先 **待确认**，再应用 |
| 上下文按会话 | 对话落库，按 `novel_id + feature_key` 分组，见 [会话与上下文](./01-会话与上下文.md) |
| 先发散再落表 | 书名/立意/人物火花等先走 [SKILL-头脑风暴](./SKILL-头脑风暴.md)，再交给 [SKILL-结构化生成](./SKILL-结构化生成.md) 对字段 |

服务端全程 **只转发、存会话、注入枚举**，不跑 LLM。

## 3. 不要拆成独立组件的东西

| 想法 | 为什么不拆 |
|------|------------|
| 每个字段一个聊天框 | 表单不可用；改走坞 + 主题 Tab |
| 立意双输入框（上结果下提示词） | 与简介、时代背景会重复三套；结果进坞，确认后写回原字段 |
| 封面生成 | 无出图链路，09 明确不做 |
| 作者名 / 进度条 | 人工字段 |
| 新 scheme | 用现有 `loop` / `react` |

---

## 4. 开发顺序

```text
01 会话表 + BFF CRUD
  → 02 坞（可先接 mock）
  → SKILL-头脑风暴 + SKILL-结构化生成（fill_basic）
  → 03 基础信息（第一条闭环：自然语言 → Tab 确认 → 写回书名/立意）
  → 04～07 按向导步骤加 fieldCatalog
  → SKILL-任务拆分 + 08
  → 09 入口
```

每份功能文档末尾有该组件自己的验收项；全链路最小验收以 03 为准。
