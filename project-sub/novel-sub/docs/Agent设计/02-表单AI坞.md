# 02 表单 AI 坞

> 类型：共用前端壳  
> 默认挂载：**竖栏，紧贴左侧菜单右侧**（独立态贴 `NavMenu` aside；嵌入主应用时贴 AMS 侧栏，作为小说内容区第一列）  
> 可切换：竖栏 `rail` ↔ 底栏 `bottom`（窄屏 / 编辑弹窗默认底栏）  
> 样式：森林风玻璃面（`--novel-color-glass` / `--novel-color-primary`）。场景卡学 cartoon-agent「图标 + 短文本」，**色与边框仍走小说令牌**，禁止 Element 默认蓝、禁止金紫聊天皮

这是 **唯一** 面向创作者的 AI 输入面。03～09 只 **插入场景卡数据** `scenes[]`，不改坞内部结构。

---

## 0. 相对旧稿改了什么

| 旧（底栏横条） | 现 |
|----------------|----|
| 坞在表单和 footer 之间，吃掉纵向空间 | 默认竖栏，表单拿满剩余宽高 |
| 扁平 `fieldCatalog` Chip | **数据插入的场景卡树**：父级 / 子集，可只选父或只选子 |
| 主题条 + 短输入，复杂树会挤乱 | 左：场景卡；右（或展开列）：**完整对话**，多轮修正 |
| 组件写死本步字段 | 父组件传入 `scenes[]`（含 `scene` / `skill` / `children`） |

表单字段本身仍不改控件；生成结果经用户确认后 `emit('apply', patch)`。

## 1. 前端

### 1.1 布局：默认竖栏贴菜单

独立运行（`:5101`）：

```
┌ 小说 NavMenu（可折叠 240/64）┬ AI 坞竖栏 ┬ 向导头 / 步骤 / 表单 / footer ┐
│ 列表                         │ 场景卡     │ 表单单独滚动，高度不被坞截断   │
│                              │ 对话       │                               │
└──────────────────────────────┴────────────┴───────────────────────────────┘
```

嵌入主应用：AMS 侧栏在子应用外。坞是 **小说 `el-main` 内最左列**，视觉上紧贴主应用菜单。

```
┌ AMS 侧栏 ┬ 小说顶栏（横向 Nav，embedded）              ┐
│          ├ AI 坞竖栏 ┬ 步骤条 + 表单 + 底栏（保存/下一步）│
└──────────┴───────────┴──────────────────────────────────┘
```

**不要**做成右上角悬浮球，也 **不要**默认再占表单下方一条 220px。

### 1.2 竖栏内部（展开态，建议 300～340px）

上 → 下：

1. **顶栏**：会话下拉、新开会话、**布局切换**（竖 / 横）
2. **场景卡**（单行横滑 Tab，**只渲染叶子**，与表单字段一一对应；父级留在 `scenes[]` 数据里表示「未选中 = 整组生成」；折叠态仍为竖向图标列）
3. **对话框**（flex:1）：历史气泡、思考过程（逻辑 + 入参标签）、助手回复（含生成正文预览）
4. **输入条**：textarea + 发送
5. **落表**：「应用到表单」/「丢弃本轮」（按当前已确认的场景 path 出 patch）

折叠态（约 56～64px，对齐菜单折叠宽）：

- 只留场景卡 **图标列**（tooltip 为 title）
- 点图标：选中该场景，并 **展开** 竖栏进入对话
- 顶上一条「展开」按钮

建议实现成 **两档宽度**，不要在 64px 里同时塞树和聊天。

### 1.3 横向模式（切换后 / 弹窗 / 窄屏）

触发：坞顶切换、视口 `< 1200px`、编辑 Dialog。

横条若再做成「Tab + 输入 + 聊天全展开」，会回到吃高度的问题。因此底栏模式约定为：

| 区域 | 常驻高度 | 行为 |
|------|----------|------|
| 场景卡 | 约 64px 横滑 | cartoon 同款：图标在上、标题在下，`nowrap` 横滑 |
| 对话 | **默认收起** | 点场景卡或「对话」展开为 **浮层/抽屉**（盖住表单下半或右侧 360px），不永久挤压表单 |

列表「AI 开书」Dialog：内容区用竖栏（Dialog 够高）或「上场景卡 + 下聊天」，与创建页同一组件、同一 `layout` prop。

`layout` 记 `localStorage`：`novel-ai-dock-layout=rail|bottom`。

### 1.4 场景卡：数据插入（组件核心）

坞 **不内置**「小说名称 / 时代背景」等文案。由所在步骤传入 `scenes`。

#### 节点结构

```ts
/** 场景卡（可递归）。用户稿里的 scean 与 scene 同义，实现用 scene。 */
export interface AiSceneCard {
  id: string
  title: string
  icon?: string
  /** Agent 场景键，决定走哪条 pipeline / action，如 world.era、basic.title */
  scene: string
  /** 写回表单的 path；父级可省略，表示「生成全部 children 的 path」 */
  path?: string
  skill?: string
  action?: string
  pipeline?: ('brainstorm' | 'writer' | 'orchestrator')[]
  applyMode?: 'replace' | 'merge' | 'append'
  placeholder?: string
  children?: AiSceneCard[]
}
```

父组件还可以传 `scenes` 以外的默认：`featureKey`、`novelId`。单卡上的 `skill` / `pipeline` **覆盖** 步骤默认。

#### 选择规则

| 操作 | 含义 | 发给 Agent 的 `target_fields` / `scene` |
|------|------|------------------------------------------|
| 未选中 / 等价于父级 | 生成本组全部叶子 | 所有子孙 `path`；`scene` 用父级（如 `world`） |
| 只勾一个子级 | 只生成这一项 | 该子 `path`；`scene` 用子级（如 `world.era`） |
| 多勾几个子级 | 联合生成 | 所选叶子 path；`scene` 用最近公共父或 `featureKey` |
| 父级 Tab | **不渲染** | 表单没有与父级同名的字段（如「世界观」），避免误当成漏字段 |

互斥：切换到**另一个父级分支**时，清掉上一分支的勾选，避免「书名 + 力量体系」这种跨步乱套（跨步请换向导 step，坞会换一整份 `scenes`）。**同一父下**多选子级是允许的。

Agent 若返回的 `target_fields` 与当前勾选不一致：对应卡出现 **虚线待确认**，用户点采纳或取消后才能「应用到表单」。禁止静默改勾选并写表单。

#### 渲染（小说风格 + cartoon 结构）

参考 `cartoon-agent` 的 `CharacterSectionNav`：**图标 + 短标题**，单卡 `flex-direction: column`（横滑条）或竖栏里 `row`（图标 18px + 标题）。

小说侧差异：

- 激活：`--novel-color-primary` 边框 + `--novel-color-primary-muted` 底，不要 `--el-color-primary`
- 只画叶子卡，不要把父级「世界观 / 基础信息」做成与叶子并列的 Tab
- 已应用到表单的叶子：标题旁极小绿点（完成勾选，可用极少量 `#B8953A` 以外的主色点，不要金边框）

竖栏场景列表用 `el-scrollbar`；叶子较多时可横滑，避免世界观 7 项挤乱对话区。

#### 插入示例（步骤 2 世界观，父/子）

父节点 `id: 'world'` 只参与未选中时的整步生成，**不要**再画一张「世界观」Tab，也不要为此补表单总览字段。

```js
[
  {
    id: 'world',
    title: '世界观',
    icon: 'MapLocation',
    scene: 'world',
    pipeline: ['brainstorm', 'writer'],
    action: 'fill_world',
    applyMode: 'merge',
    children: [
      { id: 'era', title: '时代背景', icon: 'Clock', scene: 'world.era', path: 'era', action: 'rewrite_field' },
      { id: 'geography', title: '地理环境', icon: 'Place', scene: 'world.geography', path: 'geography' },
      { id: 'social', title: '社会规则', icon: 'OfficeBuilding', scene: 'world.social_rules', path: 'social_rules' },
      { id: 'power', title: '力量体系', icon: 'MagicStick', scene: 'world.power_system', path: 'power_system' },
      { id: 'tech', title: '科技水平', icon: 'Cpu', scene: 'world.technology', path: 'technology' },
      { id: 'history', title: '历史概览', icon: 'Notebook', scene: 'world.history_notes', path: 'history_notes' },
      { id: 'timeline', title: '时间轴', icon: 'Histogram', scene: 'world.timeline', path: 'timeline', applyMode: 'append' },
    ],
  },
]
```

步骤 1 可做成多个**一级卡**（无子级）：小说名称、创作立意、简介、类型题材……与「一个父级包全部基础字段」二选一，由 03 文档给最终树；坞两种都能渲染。

### 1.5 对话框（按普通 AI 聊天做）

不再把对话压成「最近 2 轮摘要」。竖栏展开后就是标准对话流：

- 用户气泡 / 助手气泡，时间倒序或正序（建议正序 + 自动滚到底）
- 思考过程：生成中走 SSE `thinking`（token 流，面板保持展开）；`done` 后落库 `role=thinking` 并折叠
- 结构化选项卡（类型/题材/篇幅/读者/节奏）：展示但禁止选择，Agent 不生成对应枚举字段
- 助手除 `reply` 外，可挂「建议预览」折叠（书名一句话、树「将写入 n 个节点」）
- **同一会话内连续修正**：不换 `session_id`；只改当前勾选的场景。例如先生成时代背景，再说「再黑暗一点」
- 换父级场景：仍可留在同一 `feature_key` 会话（上下文连贯），但发送时带上新的 `scene` + `target_fields`
- 输入 placeholder 取 **当前焦点场景** 的 `placeholder`，没有则用步骤默认

发送中：输入禁用。失败 ElMessage，用户句是否入列见 01。

「应用到表单」：把 **本轮（或勾选的最近一轮）** `patch` 按已确认叶子 path merge 进表单，`markDirty`，不调保存 API。聊天记录保留，该轮 `applied=true`。

枚举：预览显示名称，写入 id；对不上 catalog 则禁用应用。

### 1.6 表单侧高亮

当前勾选的叶子 `path`：对应表单控件左侧 3px 主色条或轻描边。父级全选时，所有子字段一起高亮。

### 1.7 Vue 切分

| 文件 | 职责 |
|------|------|
| `AiFormDock.vue` | 布局（rail/bottom）、宽度折叠、发送/应用 |
| `AiSceneTree.vue` | 数据驱动场景卡，父/子勾选 |
| `AiChatThread.vue` | 对话 + 思考 + 预览 |
| `AiSessionSwitch.vue` | 会话列表 |
| `AiDockInput.vue` | 输入条 |

`composables/useAiDock.js`：session、turns（带 `scene`、`target_fields`、`pipeline`）、SSE。

页面：

```vue
<AiFormDock
  :feature-key="featureKey"
  :novel-id="novelId"
  :scenes="worldScenes"
  :form-snapshot="formSnapshot"
  :require-novel-id="!novelId"
  @apply="mergePatch"
/>
```

### 1.8 Props

| Prop | 说明 |
|------|------|
| `featureKey` | 见 01，会话分组 |
| `novelId` | 可空 |
| `scenes` | `AiSceneCard[]`，**必填**，插入数据 |
| `formSnapshot` | 当前步表单 + 可选其它步摘要 |
| `requireNovelId` | 向导：无草稿 id 时锁整栏（新开/发送） |
| `alwaysInteractive` | 忽略上一项，避免误走「请先保存基础信息」 |
| `sessionLocked` | 详情单章浏览态：锁新开/发送/应用；历史仍可见 |
| `lockHint` | `locked` 时提示；单章浏览默认「打开编辑后才能对话」 |
| `writeLocked` | 只锁「应用到表单/本章」，不锁聊天 |
| `layout` | 受控；不传则读 localStorage / 视口 |

## 2. 服务端

仍 **只打 01 会话 API**。turns 增加字段（BFF 原样转 Skill，自己不跑 LLM）：

```json
{
  "message": "把时代写得更乱世一点",
  "scene": "world.era",
  "target_fields": ["era"],
  "pipeline": ["brainstorm", "writer"],
  "skill": "novel-writer-skill",
  "action": "rewrite_field",
  "form_snapshot": {},
  "enum_catalog": {}
}
```

`pipeline` / `action` / `skill` 由前端根据 **当前勾选的场景卡** 解析（父级用父节点上的 pipeline；纯叶子用叶子上的，缺省则用父级）。BFF 不要猜场景。

校验：`target_fields` 必须落在当前请求允许的 path 集合内（前端根据勾选展开叶子；BFF 可用同一规则若传入完整 `scenes` 快照，一期以前端为准也可）。

## 3. Agent

坞仍不绑定死某一个 Skill。由场景卡上的 `scene` + `pipeline` 决定。

出参（对话 + 落表）：

```json
{
  "thinking": "string",
  "reply": "给人看的说明，可多轮修改的口语",
  "scene": "world.era",
  "target_fields": ["era"],
  "suggested_fields": [],
  "patch": { "era": "……" }
}
```

- `reply` 进聊天气泡，供继续改
- `patch` 仅当用户点应用才进表单
- 识别到用户想改别的子集：填 `suggested_fields`，前端对应卡待确认，**不要**擅自写进 patch

父级 `scene: "world"` 时，`patch` 可含多个子 path；叶子场景只含一个 key。

## 4. 设计补充（建议一并做）

1. **图标轨与对话列可再拆一档**：场景很多时，竖栏内再分成「左 56px 图标 / 右对话」，避免树和气泡抢同一滚动条。一期可先单列滚动。
2. **换场景是否新开会话**：默认同一 `feature_key` 会话，保证「先立意再改书名」有上下文；提供「针对当前场景新开会话」给想隔离试稿的人。
3. **底栏不要做永久聊天条**，只用图标条 + 浮层，否则横竖切换失去意义。
4. **嵌入态**坞 `z-index` 低于主应用顶栏，宽度不要让步骤条换行崩溃；表单 `min-width` 约 480px，不够则自动改 `bottom`。

## 5. 验收

- [ ] 创建页默认竖栏，表单区域高度 ≈ 整列内容区，不被底坞截成一屏只剩两三个字段
- [ ] 独立态坞紧贴小说侧栏；嵌入态坞为子应用内容最左列
- [ ] `scenes` 换一份即可从「扁平书名卡」换成「世界观父/子」，无需改坞源码
- [ ] 世界观步 Tab 与折叠项一一对应（无「世界观」总览卡）；未选中发送后 `target_fields` 含全部叶子 path；只勾「时代背景」则只有 `era`
- [ ] 对话可多轮改同一字段，点应用才写表单；未应用保存草稿不含本轮 patch
- [ ] 场景卡为图标 + 标题，激活色为叶绿令牌
- [ ] 切换 rail/bottom 后会话与勾选仍在；窄屏进入 bottom 且对话为浮层
- [ ] 未确认 Agent 建议的其它字段时，「应用到表单」禁用或不包含那些 path
