## 一、为什么「测试方案」与「测试用例」要分开

| 类型 | 特征 | 典型例子 | 方案特点 |
|------|------|----------|----------|
| **确定性** | 输入→输出可重复、无 LLM 随机性 | HTTP 404、gate 返回 429、outbox validate 拒绝 | **单次场景**即可判定 |
| **规则/状态机** | BFF 不变式、DB 状态转移 | macroPlan 五态、在途=1、幂等 | **矩阵/组合**或单次精确断言 |
| **Agent 智能** | LLM 非确定、意图/策略/文案可波动 | 意图识别、回复策略、安全审查措辞 | **多样本 + 边界 + 重复 + 统计门槛** |
| **体验/可观测** | 主观或分布性指标 | 阶段文案、TTFT、日志字段齐全 | **抽样 + 存在性/等级 SLO** |
| **非功能** | 负载、并发、长稳 | 503 硬顶、stale 回收、72h | **压测脚本 + SLO 等级** |

**结论**：[`测试项核心细节/`](./测试项核心细节/) 回答「测什么」；本文回答「**怎么测、怎样算过**」。同一测试项 ID 可绑定**一种主方案 + 一种主验证标准**（必要时加辅助方案）。

## 二、枚举总览

### 2.1 测试方案类型 `TS-*`（Test Scheme）

| 枚举 | 名称 | 适用场景 | 执行要点 |
|------|------|----------|----------|
| **TS-01-DET** | 确定性单次 | 接口、HTTP 码、探针、单次 gate | 构造一次输入，断言一次输出 |
| **TS-02-BND** | 边界/等价类矩阵 | 入参边界、状态机转移、多端载荷 | 多组输入覆盖边界，**每组独立判定** |
| **TS-03-REP** | 同用例重复抽样 | Agent 意图、策略、Pass^k | 同 prompt/场景重复 **N 次**（N 由项目配置） |
| **TS-04-SET** | 固定样本集批量 | Golden Eval、咨询 skill 回归、对抗集 | 预置样本集逐条跑，汇总统计 |
| **TS-05-CHAIN** | 多步链路串联 | 计划全链、课时 commit、E2E chain | 步骤序列，**任一步失败则链失败** |
| **TS-06-PAIR** | 对照/跨端对比 | 三端载荷边界、会员 vs 教练同句 | 同一输入在不同端/状态下对比 |
| **TS-07-NEG** | 异常/对抗专项 | 注入、医学越界、恶意 tool | 负向用例集，期望**阻断或降级** |
| **TS-08-OBS** | 可观测稽核 | journey、日志 19 项、SLS 字段 | 跑通后查日志/DB，字段存在且合理 |
| **TS-09-LOAD** | 压测/容量 | 并发、队列硬顶、多实例幂等 | 工具加压，看指标与症状 |
| **TS-10-MAN** | 人工评审 | 计划安全性、医学边界、UX 自然度 | 专家按 rubric 打分，**多数一致** |

### 2.2 验证标准类型 `VS-*`（Validation Standard）

| 枚举 | 名称 | 含义 | 典型通过条件（不含具体数值） |
|------|------|------|------------------------------|
| **VS-01-EXACT** | 精确匹配 | 单次可判 | 如：路径不存在→404；缺 Key→401 |
| **VS-02-CONTRACT** | 契约通过 | schema/validator | validateCoachOutbox、gates 返回通过 |
| **VS-03-ZERO** | 零违规 | 禁止项不得出现 | 会员端零 plan_form；零双写库 |
| **VS-04-CHAIN-OK** | 链路全过 | 多步方案 | TS-05 每一步断言均满足 |
| **VS-05-PRESENCE** | 存在性 | 字段/日志/event | interaction_log_id、journey 站点存在 |
| **VS-06-COMPLETE** | 完整性 | 结构齐全 | journey S1–S6 齐全；日志 19 项无缺失 |
| **VS-07-RATE-L** | 达标率·低门槛 | 统计类 | 样本集中通过比例 ≥ **项目配置的 L 阈值** |
| **VS-07-RATE-M** | 达标率·中门槛 | 回归/发版 | 同上，**M 阈值**（高于 L） |
| **VS-07-RATE-H** | 达标率·高门槛 | 验收/UAT | 同上，**H 阈值**（最高） |
| **VS-08-PASSK** | Pass^k 稳定 | 重复方案 | N 次重复至少 M 次满足（M/N 由项目配置） |
| **VS-09-BLOCK** | 安全阻断 | 对抗/负向 | 对抗集**全部或高比例**触发阻断/拒绝（等级 L/M/H） |
| **VS-10-SLO-L/M/H** | 性能 SLO 等级 | 延迟/吞吐 | p99/TTFT/错误率满足 **L/M/H 档 SLO**（项目配置） |
| **VS-11-MAJORITY** | 人工多数 | 专家评 | 评审员**多数**判定合格 |

> **说明**：凡 `RATE`、`PASSK`、`SLO`、`BLOCK` 的**具体比例/毫秒/次数**不在本文固定，由 [`项目阈值配置表`](./测试方案核心细节与方案关系/00-阈值配置说明.md) 或发版前测试计划单独约定。

### 2.3 方案 ↔ 验证 推荐配对

| 方案 TS | 常用验证 VS | 说明 |
|---------|-------------|------|
| TS-01-DET | VS-01-EXACT、VS-02-CONTRACT | 一次即判 |
| TS-02-BND | VS-01-EXACT、VS-02-CONTRACT | **每组**都要过 |
| TS-03-REP | VS-08-PASSK、VS-07-RATE-* | 看重复稳定性 |
| TS-04-SET | VS-07-RATE-M/H | 看样本集达标率 |
| TS-05-CHAIN | VS-04-CHAIN-OK | 链路逐步断言 |
| TS-06-PAIR | VS-03-ZERO、VS-01-EXACT | 对照端差异 |
| TS-07-NEG | VS-09-BLOCK、VS-03-ZERO | 负向必须拦 |
| TS-08-OBS | VS-05-PRESENCE、VS-06-COMPLETE | 跑后稽核 |
| TS-09-LOAD | VS-10-SLO-*、VS-01-EXACT | 指标+错误码 |
| TS-10-MAN | VS-11-MAJORITY | 人判 |

## 三、按测试维度：默认方案与验证标准

与 [`测试用例分类体系`](./测试用例分类体系.md) 维度 A–H 对齐。

| 维度 | 主导方案 TS | 主导验证 VS | 备注 |
|------|-------------|-------------|------|
| **A 层级** | A1→TS-01/02；A4→TS-05；A6→TS-04/10 | 契约 VS-02；E2E VS-04；Eval VS-07-RATE-M | 站级偏 DET，E2E 偏 CHAIN |
| **B 六站** | B2/B3→TS-01/02；B4→TS-02/01；B5 Agent 段→TS-03/04 | gate VS-01；幂等 VS-01；gates VS-02 | Pi 段若测 LLM 用 SET/REP |
| **C 业务** | 状态机→TS-02；主链→TS-05；意图/策略→TS-03/04/10 | 载荷 VS-03；确认 VS-04；意图 VS-07-RATE-H | 教练链 CHAIN+CONTRACT |
| **D 接口** | **TS-01-DET** + TS-02-BND | **VS-01-EXACT** | 最典型「一次场景即过」 |
| **E Agent** | **TS-03/04/07/10** | **VS-07-RATE-*、VS-08-PASSK、VS-09-BLOCK** | 不与接口同标准 |
| **F 非功能** | TS-09-LOAD、TS-01 | VS-10-SLO-*、VS-01-EXACT | 症状表 F5 用 DET 复现 |
| **G UX** | TS-03（文案波动）、TS-08、TS-10 | VS-07-RATE-M、VS-05、VS-11-MAJORITY | 阶段文案可 REP+RATE |
| **H 可观测** | **TS-08-OBS** | **VS-05/06** | 与功能 pass 独立稽核 |

## 五、示例对照（说明差异）

### 5.1 接口：路径不存在（确定性）

| 项 | 内容 |
|----|------|
| 测试项 | `D2-SUB-001` 缺 session_id → 400 |
| **方案** | **TS-01-DET**（POST 一次） |
| **验证** | **VS-01-EXACT**（HTTP=400，body 含 error） |
| 是否重复 | 否，一次即过 |

### 5.2 Agent：意图识别（非确定性）

| 项 | 内容 |
|----|------|
| 测试项 | `C1-INTENT-*`、`E1-PATH-001` |
| **方案** | **TS-04-SET**（意图样本集：问答/生成/修改/记录/确认各若干）+ **TS-03-REP**（边界句重复） |
| **验证** | **VS-07-RATE-H**（验收档达标率）+ 边界类 **VS-01-EXACT**（如「好的」不得写库须 100%） |
| 是否单次 | 否，需多样本 + 统计 |

### 5.3 BFF gate：待确认计划不作课时依据（规则）

| 项 | 内容 |
|----|------|
| 测试项 | `C4-PLAN-ST-003`、`C1-MACRO-011` |
| **方案** | **TS-02-BND**（状态：无/草稿/待确认/已生效 矩阵） |
| **验证** | **VS-02-CONTRACT**（gate 输出 message_type/拒绝生成） |
| 说明 | 每条状态组合精确判定，非概率 |

### 5.4 安全审查：疼痛+生成练腿

| 项 | 内容 |
|----|------|
| 测试项 | `C1-STRAT-001`、`E1-PATH-005`、`E5-*` |
| **方案** | **TS-07-NEG** + **TS-04-SET**（风险 prompt 集） |
| **验证** | **VS-09-BLOCK**（阻断率 H 档）+ **VS-03-ZERO**（不得出现 session_plan 载荷） |

## 六、与核心细节表的衔接方式

1. **测试项 ID** 不变（来自 [`测试项核心细节/`](./测试项核心细节/)）。
2. 每个 ID 在 [`测试方案核心细节与方案关系/`](./测试方案核心细节与方案关系/) 中增加列：**方案 TS**、**验证 VS**、**辅助方案**（可选）、**样本/重复说明**（可选）。
3. 发版测试计划：选定 **VS-07-RATE-M** 时，在 [`00-阈值配置说明.md`](./测试方案核心细节与方案关系/00-阈值配置说明.md) 填写当次 M 的具体百分比/次数。
4. 自动化：`TS-01/02/05` 优先落地 CI；`TS-03/04/07/10` 进 Eval 流水线或人工轮次。
