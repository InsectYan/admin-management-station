# 文档 ↔ 数据库字段对照

> testgen-sub 内 Fitness 测试资产的文档—数据关系真源说明。

---

## 1. 测试项明细

| DB 表 / 字段 | 文档来源 | 说明 |
|--------------|----------|------|
| `test_item_detail.item_id` | `测试项核心细节/*.md` 表格「测试项 ID」 | 用例编号 |
| `test_item_detail.source_doc` | 文件名，如 `B-六站流水线.md` | 所属核心细节表 |
| `test_item_detail.source_section` | 表内小节标题 | 可选定位 |
| `test_item_detail.detail_summary` 等 | 同表「测试核心细节」「预期」列 | 人工/脚本同步 |

**规则**：在核心细节表增删改测试项 → 同步 `database/tables/test_item_detail/data.json` + `init.sql`（有 INSERT 时两者都要改）。

---

## 2. 方案与验证（TS / VS）

| DB 表 / 字段 | 文档来源 | 解析优先级 |
|--------------|----------|------------|
| `test_item_detail.scheme_primary_id` | `*-方案映射.md` 或 `scheme-map.json` | ① prefix 表 → ② scheme-map → ③ 子类默认 |
| `test_item_detail.validation_primary_id` | 同上 | 同上 |
| `test_item_detail.scheme_secondary_id` | 映射表「辅助方案」列 | 同上 |
| `test_item_detail.scheme_mapping_source` | 映射文件名或 `scheme-map.json` | 记录命中规则来源 |
| `test_item_detail.sample_execution_note` | 映射表「样本/执行说明」列 | — |
| `test_item_prefix_scheme.*` | `*-方案映射.md` 解析 | 前缀级显式规则 |
| `test_category_minor_scheme.*` | `scheme-map.json` + 维度默认 | 子类默认方案 |

**规则**：改 `测试方案核心细节与方案关系/*-方案映射.md` → 运行 `sync-scheme-mapping-from-docs.js --write` → `resolve-item-schemes.js` 已内嵌于 sync 流程。

## 4. 脚本索引

| 脚本 | 输入 | 输出 |
|------|------|------|
| `backend/scripts/sync-scheme-mapping-from-docs.js` | `docs/fitness-test-docs/测试方案核心细节与方案关系/` | `test_item_prefix_scheme/data.json`，并触发 item 补全 |
| `backend/scripts/resolve-item-schemes.js` | `scheme-map.json` + prefix 表 + 子类默认 | `test_item_detail` TS/VS 字段 |
| `backend/scripts/lib/scheme-mapping-parser.js` | `*-方案映射.md` | 前缀规则数组 |

---

## 5. 上游同步（可选）

若 `fitness-agent-test-docs` 有独立更新，可整目录覆盖本副本后重新跑 sync：

```powershell
$src = "..\..\..\..\..\fitness-agent-test-docs"
$dst = ".\docs\fitness-test-docs"
Copy-Item "$src\测试用例分类体系.md" $dst -Force
# … 其余文件同 README
node backend/scripts/sync-scheme-mapping-from-docs.js --write
```

覆盖后须 `--check` 确认 `scheme_mapping_source` 与映射表一致。
