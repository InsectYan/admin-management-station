## 一、Agent 测试十条目标（PRD）

[`PRD中测试细节重点.md`](./PRD中测试细节重点.md) §1 定义 Agent 测试验收核心，所有用例应能回溯到下列目标：

| # | 目标 | 主要分类 |
|---|------|----------|
| 1 | 听懂用户想干什么（意图） | E1、C1 §4.2 |
| 2 | 找到正确身份、会员、业务对象 | C1 §4.1、C3 §6.9、D3 |
| 3 | 进入正确任务流程 | C1/C4 状态机、B4 gates |
| 4 | 使用正确上下文 | E3、C1 入口 |
| 5 | 选择正确回复策略 | C1 §4.7、E1 |
| 6 | 遵守权限、状态、安全、确认规则 | B2、C2/C3 边界、C1 §4.8/4.10 |
| 7 | 返回前端可正确渲染的数据结构 | C4 载荷矩阵、D5 SSE |
| 8 | 不在错误端返回不该返回的业务数据 | C2/C3 载荷、PRD §7.1 |
| 9 | 不重复生成、不重复写库 | B3 幂等、C1 §4.11、D2 |
| 10 | 关键过程可追踪、可复盘 | **H 可观测**、PRD §7.3 |

## 二、业务与架构重点

### 2.1 三端定位（PRD §2）

| 端 | 定位 | 测试重心 |
|----|------|----------|
| **教练** | 核心 Agent：计划/课时/总结/评估/确认 | C1（P0 主链） |
| **会员** | 轻问答+查看+确认/反馈，**禁止**生成训练业务对象 | C2 载荷边界（P0） |
| **店长** | 管理查询+分配，**禁止**生成/确认训练内容 | C3 权限+载荷（P1） |

### 2.2 技术主链（async-only，架构图 §4）

```text
① 前端 submit/stream（SSE）
→ ② 门禁（Key / 熔断 / 限流 / 在途 / 归属）
→ ③ turn_jobs 入队 + Worker 抢单（202 立即返回）
→ ④ Pipeline（prepare → Pi → gates → persist）
→ ⑤ Pi（LLM + tools + outbox.json，不写业务表）
→ ⑥ SSE 回传 + chat_messages 落库
```

**旁路**：记忆 wake/睡梦、知识库 wiki、套壳 JWT、可观测（SLS / OTel / turn_journeys）。

### 2.3 部署与并发（架构图 §2–3）

- 多实例 N；每实例 1 BFF + 1 Worker + 最多 **W** 路 Pi；共享 RDS + NAS + LLM。
- **C_pi ≈ min(N×W, C_llm)**；submit 与 claim **可跨实例**。
- **同 session 串行**（在途=1）；**跨 session 并行**。

### 2.4 Pi 能做 / 不能做（架构图 + 代码）

| Pi 能做 | Pi 不能做 |
|---------|-----------|
| 读 workspace/模板、调 LLM、只读 tools、写 outbox | 直接 UPDATE 业务表 |
| 可选 memory_ops（BFF 异步 merge） | 自己抢 turn_jobs 队列 |
| | 绕过门禁/限流 |

### 2.5 架构铁律（测试不变式）

| 铁律 | 配置/代码 |
|------|-----------|
| client_turn_id 幂等 | turnJobStore · PRD §4.11 |
| 同 session 在途=1 | TURN_SESSION_MAX_INFLIGHT |
| 待确认计划不作课时依据 | macroPlan gate · PRD §4.4/4.5 |
| 写库仅「确认」或按钮 | PRD §4.10 |
| 生产 Internal Key | INTERNAL_API_KEY |

## 四、分类体系（大类 → 子类）

| 站 | 大类 | 关键子类 | PRD/架构关联 |
|----|------|----------|--------------|
| B1 | ① 前端 | 幂等、SSE、resume、queue_meta UX | §4.12 阶段反馈 |

#### C4 业务状态机（PRD §7.2，测试必覆盖）
