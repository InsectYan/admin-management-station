## 2. 分模板缺口与卡点

### TPL-DET（确定性单次）

| ID | 类型 | 说明 |
|----|------|------|
| DET-01 | 已变更 | UI 已从「完整接口模板 + inject」改为 **preflight 取参**；旧字段保存时强制清空 |
| DET-02 | 体验 | 可抛出字段有引导，但全局变量仍无可点选列表 |
| DET-03 | 卡点·校验已前移 | poll / `{{turn_id}}`：launch 前 `validateDetLaunchPreconditions`（缺 preflight 或未勾选执行主请求直接 400） |
| DET-04 | 文档 | 设计稿未同步 preflight / 可编辑 method / assertions |

**缺失功能**：主请求侧样本集注入（刻意迁出到 API-CTX）。

---

### TPL-BND（边界矩阵）

| ID | 类型 | 说明 |
|----|------|------|
| BND-01 | 能力缺口 | **无前置接口模板关联**；复杂会话需手填 ID 或改 CHAIN/API-CTX |
| BND-02 | 字段 | Panel 字段偏精简（runner/path/method/expect）；body/headers 行级编辑完整度需对照最新 UI |
| BND-03 | 设计 | 「从 test_steps 自动生成矩阵」未做 |

---

### TPL-REP（重复抽样）

| ID | 类型 | 说明 |
|----|------|------|
| REP-01 | 能力缺口 | **无 preflight**；动态 `session_id`/`turn_id` 难自动获取 |
| REP-02 | 体验 | 与样本集/Judge 联动说明分散，配置页引导不足 |
| REP-03 | 耗时 | N 次全量串/并行对 BFF 压力大，缺「干跑 / 限流」提示 |

---

### TPL-SET（固定样本集）

| ID | 类型 | 说明 |
|----|------|------|
| SET-01 | 联调 | Agent Judge / `agent_judge` 落库依赖 Agent 仓联调（评分 P0） |
| SET-02 | 能力 | 样本内 `{{var}}` 渲染能力弱于 DET；鉴权靠环境头 |
| SET-03 | 产品 | CSV 智能补全、job 导入样本集仍在 P1 清单 |

---

### TPL-CHAIN（多步链路）

| ID | 类型 | 说明 |
|----|------|------|
| CHAIN-01 | **卡点·已修** | 初始 vars **已合并** `globalRequestContext.vars`（与 DET 对齐） |
| CHAIN-02 | 体验 | 无接口模板选择；多用例重复链路需复制 steps 或改用 API-CTX |
| CHAIN-03 | 混合 TS | C1–C4 默认偏向 api_ctx 时，用户可能误留在 CHAIN 空配置 |

**建议**：需要全局 openid/token 插值时，先写入 `config_json.vars` 明文/占位，或改用 DET/API-CTX。

---

### TPL-API-CTX（前置链路+接口模板）

| ID | 类型 | 说明 |
|----|------|------|
| API-01 | **卡点·已修** | runner 初始变量 **已合并** 项目全局 vars（`globalRequestContext.vars` + input_params） |
| API-02 | 依赖 | 强依赖接口模板质量；模板 preflight/poll 配错时用例侧难排查 |
| API-03 | 文档 | 旧文档把 inject 写在 DET，导致配置迷路 |

---

### TPL-PAIR（对照对比）

| ID | 类型 | 说明 |
|----|------|------|
| PAIR-01 | **卡点** | 无 **per-role 凭证**；多端 JWT 无法在一行列切换 |
| PAIR-02 | 能力 | 无前置链路；对照前数据准备需外部完成 |
| PAIR-03 | 断言 | `forbidden_patterns` 较粗糙，无 JSONPath 级对照 |

---

### TPL-NEG（对抗专项）

| ID | 类型 | 说明 |
|----|------|------|
| NEG-01 | 字段 | 对抗 payload / body 在 Panel 的完备度因版本而异，需对照引擎 |
| NEG-02 | 安全 | 无环境级「禁止打生产」护栏 |
| NEG-03 | 样本 | 与文本样本集联动弱于 API-CTX inject |

---

### TPL-OBS（可观测稽核）

| ID | 类型 | 说明 |
|----|------|------|
| OBS-01 | 卡点 | `session_id`/`turn_id` **是否插值** 与 DET 不一致风险；常需手工粘贴 |
| OBS-02 | 依赖 | journey / OTel / Jaeger 未就绪时检查 skip 或失败，环境探活未覆盖全部探针 |
| OBS-03 | 设计 | H1–H8「专用子面板」未拆，共用同一 checks 表 |

---

### TPL-LOAD（压测容量）

| ID | 类型 | 说明 |
|----|------|------|
| LOAD-01 | **未完成** | **真实 k6 执行未集成**（P2）；现为进程内并发 + 可导出脚本 |
| LOAD-02 | 变量 | 不完整走 globalRequestContext 插值链路 |
| LOAD-03 | 解读 | `analyze_load_run` / Agent 压测解读未闭环 |

---

### TPL-MAN（人工评审）

| ID | 类型 | 说明 |
|----|------|------|
| MAN-01 | 体验 | 打分 UI / AI 预审在评分清单中仍有推进项（P1） |
| MAN-02 | Agent | `agent_skill=null`，无配置生成 |
| MAN-03 | 流程 | 多人评审状态机、催办与报告聚合完整度不足 |

## 3. 按严重度优先修复建议

### P0（阻塞正确性 / 易踩坑）

1. **ENV-01 / X-03**：**代码已修**（须部署 migration `038`）；Launch/环境页按项目拉环境  
2. **CHAIN-01 / API-01**：**已修**，初始 vars 合并 `globalRequestContext.vars`  
3. **X-02**：extract 仍不注入；**提示已加强**（手册 / 环境页 / DET 错误）  
4. **DET-03**：**已修**，launch 前 `validateDetLaunchPreconditions`  

> 执行期 AI 自动补齐前置与卡点映射见 [计划-执行期配置AI自动补齐.md](./计划-执行期配置AI自动补齐.md) §2。Phase P 两轮完成后可进入 Phase 0。

### P1（体验与一致性）

1. 配置页全局变量选择器（X-01）  
2. PAIR per-role headers（PAIR-01）  
3. 同步修订两份设计文档（X-04）  
4. OBS 会话键插值与 DET 一致（OBS-01）

### P2（能力增强）

1. 真 k6 集成 + 结果解析（LOAD-01）  
2. BND/REP 可选 preflight  
3. MAN 打分与 Agent 预审闭环  
4. 大类 variant 专用编辑器（X-05）
