# fitness-agent · 数据库自动化同步

> 将 fitness-agent **已落地**的单测映射到 testgen-sub 主表 `test_item_detail`，供平台展示「是否自动化」与「执行命令」。

---

## 涉及表

| 表 | 字段 | 说明 |
|----|------|------|
| `test_item_detail` | `automation_status_id` | `AUTO_EXISTING` / `AUTO_TODO` / `AUTO_PARTIAL` / `AUTO_MANUAL` |
| `test_item_detail` | `automation_entry_id` | 关联 `automation_entry_enum` |
| `test_item_detail` | `automation_command` | 可复制的 shell 命令 |
| `test_item_detail` | `code_reference` | 测试源码路径 |
| `automation_entry_enum` | `command` | 站级 / E2E 入口命令模板 |

枚举数据：`database/tables/automation_entry_enum/`（含 `AUTO_S01` ~ `AUTO_S06`、E2E 入口等）。

---

## 同步流程

在 **testgen-sub 根目录**（或任意目录，脚本用相对路径定位 `data.json`）：

```bash
# 1. 编辑 PATCH 映射（新增 item_id → 自动化字段）
#    test-project/fitness-agent/scripts/sync-automation-status.mjs

# 2. 写回 data.json
node test-project/fitness-agent/scripts/sync-automation-status.mjs

# 3. 注入 Postgres（需 ams-testgen 本地库在跑）
cd deploy && ams-testgen db:seed test_item_detail
# 或全量：ams-testgen db:seed
```

```javascript
"ITEM-ID": {
  automation_status_id: "AUTO_EXISTING",
  automation_entry_id: "AUTO_S02",  // 按站选择
  automation_command: "cd server && npm run test:stations -- <filter>",
  code_reference: "server/src/stations/.../xxx.test.ts",
}
```

---

## 命令书写规范

- 统一前缀 `cd server &&`，与 `automation_entry_enum` 中现有条目一致
- filter 与 [站级测试清单.md](./站级测试清单.md) 一致
- 需 LLM / Docker 全栈的用例保持 `AUTO_TODO` 或 `AUTO_E2E_*` 入口，不要标为站级 `AUTO_EXISTING`

---

## 与平台 UI 的关系

testgen-sub 前端「用例详情 / 自动化状态 / 执行命令」读取 `test_item_detail` 及 JOIN 的枚举中文名。  
修改 `data.json` 后**必须** `db:seed` 才会在 UI 生效；仅改 JSON 不 seed 则 DB 仍为旧值。
