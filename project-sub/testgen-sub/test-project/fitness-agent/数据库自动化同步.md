# fitness-agent · 数据库自动化同步

> 将 fitness-agent **已落地**的单测映射到 testgen-sub 主表 `test_item_detail`，供平台展示「是否自动化」与「执行命令」。

---

## 涉及表

| 表 | 字段 | 说明 |
|----|------|------|
| `test_item_detail` | `automation_status_id` | `AUTO_EXISTING` / `AUTO_TODO` / `AUTO_PARTIAL` / `AUTO_MANUAL` |
| `test_item_detail` | `automation_entry_id` | 关联 `automation_entry_enum` |
| `test_item_detail` | `automation_command` | 可复制的 shell 命令 |
| `test_item_detail` | `code_reference` | 测试源码路径 |
| `automation_entry_enum` | `command` | 站级 / E2E 入口命令模板 |

枚举数据：`database/tables/automation_entry_enum/`（含 `AUTO_S01` ~ `AUTO_S06`、E2E 入口等）。

---

## 真源说明（重要）

| 文件 | 用途 |
|------|------|
| `data.json` | 平台 API / enrich 展示 |
| `init.sql` 内 INSERT | **`db:seed` 实际注入 Postgres 的数据** |

当表目录同时存在 `init.sql` INSERT 与 `data.json` 时，`db-cli.js` **只读 init.sql**，且 `ON CONFLICT DO NOTHING` 不会更新已有行。  
因此同步脚本须 **同时写 data.json 与 init.sql**；对已有库须 **`db:reset test_item_detail`**，不能指望单独 `db:seed` 刷新自动化字段。

Cursor 开发规则：[`fitness-agent-test-automation-sync.mdc`](../../../../.cursor/rules/fitness-agent-test-automation-sync.mdc)

---

## 同步流程

在 **testgen-sub 根目录**：

```bash
# 1. 编辑 PATCH 映射（新增 item_id → 自动化字段）
#    test-project/fitness-agent/scripts/sync-automation-status.mjs

# 2. 写回 data.json + init.sql（脚本会校验 AUTO_EXISTING 计数）
node test-project/fitness-agent/scripts/sync-automation-status.mjs

# 3. 注入 Postgres（需 ams-testgen 本地库在跑）
cd deploy && ams-testgen db:reset test_item_detail
```

验证（可选）：

```sql
SELECT automation_status_id, COUNT(*)
FROM test_item_detail
WHERE is_active
GROUP BY 1;
-- 预期 AUTO_EXISTING 与脚本输出一致（当前约 59）
```

### 有意未映射（矩阵无条目或不可站级自动化）

| 单测文件 | 原因 |
|----------|------|
| `public-id.test.ts` / `text-limits.test.ts` / `member-goal-parse.test.ts` | 矩阵无对应 `item_id` |
| `outbox-preview.test.ts` / `outbox-draft-merge.test.ts` | 矩阵无独立条目 |
| `turn-submit-guard-response.test.ts` | 纯函数辅助，无独立业务项 |
| `s01-frontend.test.mjs` | 类型检查，非业务用例项 |
| E2E 项（如 C2-BOUND-004） | 保持 `test:e2e`，不标站级 EXISTING |
| LLM / 全栈 / B6-TIMEOUT-001 等 | 保持 `AUTO_TODO` |

新增单测时：在 `PATCH` 对象中追加条目，字段至少包含：

```javascript
"ITEM-ID": {
  automation_status_id: "AUTO_EXISTING",
  automation_entry_id: "AUTO_S02",  // 按站选择
  automation_command: "cd server && npm run test:stations -- <filter>",
  code_reference: "server/src/stations/.../xxx.test.ts",
}
```

## 命令书写规范

- 统一前缀 `cd server &&`，与 `automation_entry_enum` 中现有条目一致
- filter 与 [站级测试清单.md](./站级测试清单.md) 一致
- 需 LLM / Docker 全栈的用例保持 `AUTO_TODO` 或 E2E 入口，**不要**标 `AUTO_EXISTING`
- `code_reference` 多路径用逗号分隔，**勿用分号**（init.sql INSERT 按 `;` 切分）

## 与平台 UI 的关系

testgen-sub 前端「用例详情 / 自动化状态 / 执行命令」读取 Postgres 中 `test_item_detail` 及 JOIN 的枚举中文名。  
修改后须：`sync-automation-status.mjs` → `db:reset test_item_detail` → UI 才与 PATCH 一致。
