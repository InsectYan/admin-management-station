# fitness-agent · 单测缺口梳理

> 梳理范围：适合 **单测 / 站级自测**、**不依赖 LLM** 的用例缺口。  
> 依据：fitness-agent 源码、`npm run test:stations` 现有测试、[`fitness-agent-test-docs`](../../../../../fitness-agent-test-docs/测试用例分类体系.md) 测试项 ID。

## 一、现有覆盖概览

| 层级 | 入口 | 覆盖范围 |
|------|------|----------|
| **s01 前端** | `frontend/tests/s01-frontend.test.mjs` | 仅检查 API 导出存在 + 可选 `vue-tsc` |
| **s02 门禁** | `turn-submit-guard.test.ts` | 教练端：归属、空消息、限流、重复、在途、cancel、retry |
| **s03 队列** | `turn-job-store.test.ts` | 入队 + `client_turn_id` 幂等（2 个用例） |
| **s04 Pipeline** | `bff-pipeline` / `macro-plan-flow` / `session-plan-flow` | 教练 BFF gates、计划/课时状态机（较全） |
| **s05 Pi** | `s05-pi.test.ts` | `memoryOpFilter` + `validateCoachOutbox`（text / plan_form） |
| **s06 回传** | `turn-journey.test.ts` | `turn_journeys` 观测写入（非真实 SSE HTTP） |
| **E2E** | `test:e2e` | 三端 async、主链、续传（**需 LLM**） |

**结论**：教练端 BFF 门禁覆盖较好；**门禁熔断/队列硬顶、队列 Worker 生命周期、会员/店长契约、SSE 解析、Pi outbox 其余类型、platform 工具函数** 仍是明显空白。

## 二、按站梳理：缺失的单测用例

### s01 · 前端（纯函数，无 LLM/DB）

## 五、不适合单测、归 E2E / 压测的项

以下在测试文档中有定义，但 **不应** 纳入站级单测范围：

- 三端 async 对话质量、意图识别（E1 / PRD §4.2）
- 全栈计划/课时主链 UI 一致性（A4-E2E-CHAIN）
- 跨实例 submit/claim（B3-CROSS-001）
- 多实例容量、JMeter 压测（A5）
- Golden eval / mock-LLM 快照（A6）

这些保留在 `fitness-agent` 的 `npm run test:e2e` 或人工 UAT。
